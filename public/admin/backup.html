备份与恢复

这是给站点维护者使用的“备份/回滚”入口，不影响前台路由与 SEO。
返回后台
合理性说明：本项目内容（文章、设置、上传图片）最终都会提交到 GitHub 仓库，因此 Git 历史本身就是最可靠的备份。 这里的“备份/恢复”主要是为了更方便地：
  • 创建一个明确的“快照点”（tag）用于回滚
  • 生成一个可下载的压缩包（Actions artifact）用于离线保存
  • 通过 PR 安全回滚（不强推 main）

一键备份（创建 tag + 生成压缩包）

触发 GitHub Actions：Backup Snapshot。会创建形如 backup-YYYYMMDD-HHMMSS 的 tag， 并上传一份压缩包 artifact（默认有保存期限）。
去触发备份

安全恢复（从备份 ref 创建 PR）

触发 GitHub Actions：Restore From Backup Ref (PR)。输入 tag 或 commit SHA， Actions 会创建 restore 分支并发起 PR，合并即可回滚线上。
去触发恢复
